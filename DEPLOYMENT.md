# Deployment Guide — MarketPulse (fyp-2)

This app has **two deployable pieces**. They cannot both live on a Cloudflare
Worker (the Python pipeline can't run there), so:

| Piece | Tech | Host | URL |
|---|---|---|---|
| `frontend/` | Next.js 16 | **Cloudflare Workers** (OpenNext) | `https://fyp-2.charliewwww.com` |
| `backend/` + pipeline + **Google OAuth** | FastAPI (Python) | **Render** | `https://fyp-2-api.charliewwww.com` |
| PostgreSQL | managed DB | **Render** | (internal) |

Because both public URLs are subdomains of **charliewwww.com**, they are
*same-site*, so the sign-in cookie is sent automatically — no cross-site cookie
hacks needed.

> The old `fyp-final` "Hello Hono" Worker is not used by this app. You can delete
> it once `fyp-2` is live (Cloudflare dashboard → Workers → `fyp-final` → Delete).

```
Browser ──▶ fyp-2.charliewwww.com        (Cloudflare Worker: Next.js UI)
   │            │  fetch(/api/v1/*, credentials: include)
   │            ▼
   └────────▶ fyp-2-api.charliewwww.com  (Render: FastAPI + pipeline + OAuth)
                 │
                 ▼
              PostgreSQL (Render managed)
```

Do the steps **in order** — the backend URL is needed for OAuth, and the OAuth +
backend URL are needed by the frontend.

---

## 0. Prerequisites

- Push this repository to GitHub (Render + Cloudflare deploy from it).
- `charliewwww.com` should be managed in **Cloudflare DNS**. If it isn't yet:
  Cloudflare dashboard → *Add a site* → `charliewwww.com` → update the
  nameservers at your registrar. A Cloudflare Worker custom domain requires the
  zone to be on Cloudflare.

---

## 1. Deploy the backend to Render

1. **Render dashboard → New → Blueprint** and select this repo. Render reads
   [`render.yaml`](render.yaml) and provisions:
   - a web service `fyp-2-api`
   - a PostgreSQL database `fyp-2-db` (wired into `DATABASE_URL` automatically)
2. Click **Apply**. The first build installs both requirement files
   (`requirements.txt` + `backend/requirements.txt`) — this takes a few minutes.
3. When it boots you'll get a default URL like `https://fyp-2-api.onrender.com`.
   Open `https://fyp-2-api.onrender.com/health` — it should return
   `{"status":"ok",...}`.

> **Region / size:** the blueprint uses `region: singapore`. Change it if you're
> elsewhere (keep the service and database in the **same** region). The pipeline
> is memory-heavy — if runs crash with out-of-memory, upgrade the service to
> `standard` (2 GB) and/or lower `PIPELINE_MAX_WORKERS`.

### 1a. Point your domain at the backend
1. Render → `fyp-2-api` → **Settings → Custom Domains → Add** →
   `fyp-2-api.charliewwww.com`. Render shows a CNAME target.
2. Cloudflare DNS → **Add record**: `CNAME  fyp-2-api  →  <that target>`,
   **Proxy status = DNS only (grey cloud)** so Render can issue its TLS cert.
3. Wait for Render to show the domain as *Verified / Certificate Issued*.

---

## 2. Set up Google OAuth

Google is only the *identity provider*; your backend owns the session. Sign-in is
now **open** — anyone with a verified Google account gets in and their own
workspace (no invite list).

1. [Google Cloud Console → APIs & Services → Credentials](https://console.cloud.google.com/apis/credentials).
2. If needed, configure the **OAuth consent screen**:
   - User type: **External**, Publishing status: **In production** (so it isn't
     limited to test users), scopes: `openid`, `email`, `profile`.
3. **Create Credentials → OAuth client ID → Web application** (or edit your
   existing one). Set:
   - **Authorized JavaScript origins:**
     - `https://fyp-2.charliewwww.com`
     - `https://fyp-2-api.charliewwww.com`
   - **Authorized redirect URI** (must match exactly):
     - `https://fyp-2-api.charliewwww.com/api/v1/auth/callback`
4. Copy the **Client ID** and **Client secret**.

### 2a. Add the secrets to Render
Render → `fyp-2-api` → **Environment** → add / fill (these are `sync: false` in
the blueprint, so they are never committed to git):

| Key | Value |
|---|---|
| `GOOGLE_CLIENT_ID` | your Google client ID |
| `GOOGLE_CLIENT_SECRET` | your Google client secret |
| `AUTH_BOOTSTRAP_ADMIN_EMAILS` | your email (becomes the first admin) |
| `OPENROUTER_API_KEY` | your OpenRouter key (default LLM provider) |
| `DEEPSEEK_API_KEY` | your Deepseek key (optional: for switching to direct Deepseek) |
| `FRED_API_KEY` | your FRED key (optional) |
| `SEC_EDGAR_EMAIL` | a contact email for SEC EDGAR |

`SESSION_SECRET_KEY` is auto-generated by Render. Save changes — the service
redeploys. (`APP_ENV=production` makes the app refuse to boot without Google +
session secret configured, so this step is required.)

---

## 3. Deploy the frontend to Cloudflare Workers

The frontend is already wired for Cloudflare via **OpenNext**
(`wrangler.jsonc`, `open-next.config.ts`, deploy scripts). It's built to call the
backend at the URL in [`frontend/.env.production`](frontend/.env.production)
(`NEXT_PUBLIC_API_URL=https://fyp-2-api.charliewwww.com`).

From the `frontend/` folder:

```powershell
cd frontend
npx wrangler login          # once, opens a browser to authorize
npm run preview             # optional: build + run locally in the Workers runtime
npm run deploy              # builds with OpenNext and deploys the `fyp-2` Worker
```

`npm run deploy` publishes a Worker named **`fyp-2`** to
`fyp-2.<your-subdomain>.workers.dev`.

### 3a. Point your domain at the frontend
Cloudflare dashboard → **Workers & Pages → `fyp-2` → Settings → Domains & Routes
→ Add → Custom Domain** → `fyp-2.charliewwww.com`. Cloudflare creates the DNS
record and TLS automatically (this one stays **proxied / orange cloud**).

---

## 4. Verify end-to-end

1. Visit `https://fyp-2.charliewwww.com` → you should be sent to the login page.
2. Click **Continue with Google**, pick your account → you land back in the app,
   signed in.
3. Run a pipeline from the Pipeline page and confirm live progress streams.
4. Sign in with a *different* Google account → it gets its **own** empty
   workspace (its own runs, separate from yours). This confirms per-user
   isolation + open sign-up.

## Environment variable reference

**Backend (Render)** — most are set by [`render.yaml`](render.yaml); secrets are
filled in the dashboard:

| Key | Set by | Value |
|---|---|---|
| `APP_ENV` | blueprint | `production` |
| `DATABASE_URL` | blueprint | injected from `fyp-2-db` (auto-upgraded to `postgresql+asyncpg://`) |
| `SESSION_SECRET_KEY` | blueprint | auto-generated |
| `BACKEND_BASE_URL` | blueprint | `https://fyp-2-api.charliewwww.com` |
| `FRONTEND_BASE_URL` | blueprint | `https://fyp-2.charliewwww.com` |
| `CORS_ORIGINS` | blueprint | `["https://fyp-2.charliewwww.com"]` |
| `COOKIE_SECURE` / `COOKIE_SAMESITE` | blueprint | `true` / `lax` |
| `PIPELINE_MAX_WORKERS` | blueprint | `4` (raise on bigger instances) |
| `GOOGLE_CLIENT_ID` / `GOOGLE_CLIENT_SECRET` | **you** | from Google |
| `AUTH_BOOTSTRAP_ADMIN_EMAILS` | **you** | your email |
| `OPENROUTER_API_KEY` | **you** | your OpenRouter key (default) |
| `DEEPSEEK_API_KEY` | **you** | your Deepseek key (optional) |
| `FRED_API_KEY` / `SEC_EDGAR_EMAIL` | **you** | your keys |

**Frontend (Cloudflare)** — build-time:

| Key | Where | Value |
|---|---|---|
| `NEXT_PUBLIC_API_URL` | `frontend/.env.production` | `https://fyp-2-api.charliewwww.com` |

## Notes & gotchas

- **Different domain names?** If you change the subdomains, update them in *all*
  of: `render.yaml` (`BACKEND_BASE_URL`, `FRONTEND_BASE_URL`, `CORS_ORIGINS`),
  `frontend/.env.production` (`NEXT_PUBLIC_API_URL`), and the Google redirect URI.
- **`.env*` is gitignored**, so `frontend/.env.production` stays local. If you
  build the frontend in CI instead of locally, set `NEXT_PUBLIC_API_URL` as a
  build variable there too.
- **ChromaDB is ephemeral on Render** (rebuilt on each deploy). The primary store
  is PostgreSQL; the vector cache just re-warms.
- **Free Postgres** on Render is fine to start; upgrade for size/retention.
- **Cold starts:** on the `free`/`starter` plan the API may take a few seconds to
  wake after idle. Upgrade the plan to avoid it.
